## 2. 竞品对标结论（先立坐标系再开会）

**对标对象**：瓴羊 Quick BI 智能小Q（预设归因树）、思迈特 Smartbi AIChat（Agent BI）、帆软 FineBI、观远 Copilot、ThoughtSpot、Power BI Copilot。

**事实**（据 IDC《2025 中国 GenBI 厂商技术能力评估》及公开资料）：
- 赛道正从 ChatBI"一问一答"升级为 Agent BI"多步归因 + 报告闭环"；
- 技术路线分两派：预设归因路径（Quick BI）vs 自主 Agent 编排（思迈特）；
- 共同短板：归因过程不透明、证据不可回溯、演示绑定厂商生态。

**判断（本项目机会位）**：
- 需求文档的"工具执行 + 六段式输出 + 长连接过程可见"= 自主 Agent 分析路径 + 结构化输出约束的**混合体**；
- 差异化卖点：证据链可回溯（source_type/source_name/confidence）+ 多业务场景自带示例数据；
- 风险点：纯自主 Agent 演示易翻车 → 需混合路线约束（已转化为第一轮决策 1）。

## 3. 第一轮拷问（骨架决策 × 4）

### 3.1 归因引擎技术路线
- 选项：A 混合（Agent 自主 + 结构化约束）/ B 纯自主 Agent / C 预设归因流程
- **决策：A 混合路线**（推荐项）。理由：兼顾开放性与可解释性，演示最稳。
- 后续影响：架构（6.6）、风险清单第 1 条。

### 3.2 认证方案（初选 → 因"企业级上云"重议）
- 初选：A 自建最小 OAuth2/OIDC / B 对接 Keycloak / C 内置简化登录。
- 中途信息变更：爸爸补充**企业级、上线云服务器** → SQLite 出局，认证口径重新确认。
- **重议决策：自建 OIDC 认证中心**（授权码模式，同仓库独立 schema `auth_`、独立容器）。
- 理由：协议走标准 OAuth2/OIDC 企业级站得住；后续换 Keycloak/企业 IdP 只改客户端配置；单仓库交付。

### 3.3 技术栈（企业级口径）
- 选项：A FastAPI + Vue3 + MySQL / B Spring Boot + Vue3 + MySQL / C Go(Gin) + Vue3 + MySQL
- **决策：FastAPI + Vue3 + MySQL + Redis**（推荐项）。理由：LLM/Agent 生态最成熟；异步框架支持 WS；Docker 部署成熟。

### 3.4 演示场景（6 选 2）
- 选项：A 商品目录优化 + 库存异常分析 / B 客户行为 + 退款模式 / C 市场表现 + 评论反馈 / D 全做
- **决策：A 商品目录优化 + 库存异常分析**。理由：一个管"卖什么"、一个管"备多少"，归因逻辑直观，表结构清晰，叙事连贯。

## 6. 资源规格修订（4C8G → 2C2G）

- **新约束**：爸爸确认云服务器为 4核4G，本项目最多用一半 → **目标规格 2C2G**。
- **修订内容**（PRD v1.1，共 6 处）：技术栈表、部署拓扑（加容器内存配额）、WS 并发（≤10/≤3）、11.1 性能节重写（含 2G 内存预算表）、风险清单第 5 条。
- **关键设计判断**：
  - LLM 推理在云端 API 完成，本地仅流式转发 → 2C2G 主要瓶颈是 backend 进程内存与并发任务数；
  - 硬性设计：backend 单 worker + 同时运行任务 ≤3；附件解析限并发 1（峰值约 200~300MB）。
- **内存预算表（2048MB）**：mysql 400 / backend 600 / auth 180 / redis 180 / frontend 40 / 预留 650。

## 3. 「询问没有反应」问题：根因与修复

### 3.1 根因链（三层叠加）

| # | 层 | 根因 | 证据 |
|---|---|---|---|
| 1 | **后端** | 同一会话存在 `queued/running` 任务时，`/api/chat/send` 抛 **TASK_BUSY (409)** 拒绝 | `app/domains/task/service.py` 互斥检查；实测任务 `01a019eadb...` 12:07:39 已 success，但此前运行期提问会被拒 |
| 2 | **前端** | `send()` 失败仅 `toast` 一闪（3.2s），**已清空输入框 + 乐观插入的用户消息残留** → 用户感知「消息发了但没反应」 | `frontend/src/views/ChatView.vue` `send()` catch 块 |
| 3 | **前端** | WS 断线/终态事件丢失后 UI 卡在 `running`，无主动恢复 → 用户持续在"运行中"误状态下提问 | 截图会话「11」UI 显示 running，后端实际 success |
| 4 | **前端** | 中文输入法（IME）组合态下按 Enter 被 `@keydown.enter.exact` 拦截 → 候选词无法上屏，体感"按键无反应" | `ChatView.vue` textarea 事件绑定 |

### 3.2 已实施的修复

**前端 `frontend/src/views/ChatView.vue`**
1. `send()` 失败时**撤回乐观插入的用户消息 + 恢复输入框内容**，杜绝"消息消失"
2. 按错误码给出明确提示并延长展示：`TASK_BUSY`（等待/取消后重试）、`TASK_QUEUE_FULL`（稍后再试）、401（重新登录），默认错误 6s
3. 未选中会话时提示「请先选择或新建分析任务」，不再静默 return
4. **IME 兼容**：新增 `composing` 状态，`@compositionstart/end` 跟踪输入法组合态，组合中按 Enter 仅上屏候选词、不触发发送（`onEnterSend`）

**前端 `frontend/src/App.vue` + `main.js`**
5. toast 支持 `duration` 参数（默认 3200ms，错误 6000ms）

**后端 `app/domains/task/router.py`**
6. 生成 WS token 时**顺带清理过期 token 行**，防止 `websocket_tokens` 表无限膨胀（上线后注意：需重建 backend 容器生效）

### 3.3 生效方式

```bash
# 重建前端（nginx 容器加载新 dist）
docker compose up -d --build frontend
# 重建后端（让 token 清理逻辑生效，可选）
docker compose up -d --build backend
```

> ⚠️ 已修改的源码在宿主机项目目录，但**运行中的容器仍是旧镜像**，必须重建容器才会生效。

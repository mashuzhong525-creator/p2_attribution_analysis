# 部署运维文档

适用版本：仓库基线（commit `8e5c0b0` 及以后）。目标环境：单机 Docker（云服务器 4C4G，本项目按 **2C2G** 收敛）。

## 1. 部署拓扑

| 服务 | 容器 | 端口 | 说明 |
|---|---|---|---|
| mysql | `bia-mysql-1` | 3306 | MySQL 8.0，业务库 `bia` + 场景库 `scenario_goods` / `scenario_inventory`，数据卷 `bia_mysql_data` |
| redis | `bia-redis-1` | 6379 | Redis 7，WS seq / 分布式锁，`appendonly` 需开启（见 §5） |
| backend | `bia-backend-1` | 8000 | FastAPI：REST + WS + 认证中心 + 归因引擎 + 任务队列（3 worker） |
| frontend | `bia-frontend-1` | 8080 | nginx 托管 Vue 构建产物，`/api` 与 `/api/ws` 反代 backend |

Compose 顶层 `name: bia`：所有容器/网络/卷以 `bia-` 前缀命名，与主机上其它项目完全隔离。

## 2. 初始化流程（容器启动自动完成）

```
bia-mysql-1     首次建卷 → 执行 scripts/mysql-init/01-scenario-dbs.sql
                         （预建 scenario_* 库 + 授权 bia 用户）
bia-backend-1   entrypoint.sh：
                 1) 等待 MySQL 就绪
                 2) alembic upgrade head        （17 张表 + 13 索引）
                 3) python -m scripts.seed      （31 项配置 / auth_users / auth_clients / users / data_sources）
                 4) FLAG_SCENARIO_DATA=true → 生成场景一/二示例数据（确定性 seed=2026）
                 5) python -m scripts.seed_demo_conversations
                                                 （两组完整演示会话：会话/消息/任务/六段式结果/日志/LLM，幂等）
                 6) uvicorn app.main:app        （lifespan：工具注册→ConfigCache→OIDC 密钥→任务队列→WS 心跳）
```

## 3. 快速启动

```bash
docker compose up -d --build        # 构建并启动四服务
docker compose ps                   # 等待全部 healthy
# 访问 http://localhost:8080（admin / admin123，首次登录需修改密码）
```

## 4. 环境变量清单

在项目根目录建 `.env`（参照 `.env.example`），或直接在 shell 导出。**任何密钥不要写入 git。**

| 变量 | 默认值 | 生产必填 | 说明 |
|---|---|---|---|
| `APP_ENV` | `prod` | — | `prod`：Cookie 仅 HTTPS 下发；开发用 `dev`（echo SQL、非 secure cookie） |
| `DB_HOST / DB_PORT` | `mysql / 3306` | — | 容器内为服务名 |
| `DB_USER / DB_PASSWORD / DB_NAME` | `bia / bia_password / bia` | ✅ DB_PASSWORD | 业务库账号；DB_PASSWORD 必须与 MYSQL_PASSWORD 一致 |
| `MYSQL_ROOT_PASSWORD` | `root_password` | ✅ | MySQL root（仅初始化用） |
| `MYSQL_DATABASE / MYSQL_USER` | `bia / bia` | — | 容器初始化库/账号 |
| `REDIS_HOST / REDIS_PORT / REDIS_PASSWORD` | `redis / 6379 / 空` | 按需 | — |
| `OIDC_ISSUER` | `http://backend:8000` | ✅ | 容器内 JWT issuer；对外经网关访问时改为公网 HTTPS 地址 |
| `OIDC_CLIENT_ID / OIDC_CLIENT_SECRET` | `bia-web / change-me-client-secret` | ✅ secret | 认证客户端 |
| `OIDC_REDIRECT_URI` | `http://localhost:8080/auth/callback` | ✅ | 前端回调地址 |
| `OIDC_RSA_PRIVATE_KEY` | 空（启动生成临时密钥） | ✅ | RSA PEM 私钥；不设则重启后已签发 JWT 全部失效 |
| `APP_ENCRYPTION_KEY` | 空（退化派生） | ✅ | Fernet key（`python -c "import base64;print(base64.urlsafe_b64encode(b'a'*32).decode())"` 生成） |
| `FLAG_SCENARIO_DATA` | `true` | — | 是否生成/使用场景示例数据 |
| `FLAG_COMMAND_EXEC` | `false` | — | command_exec 工具开关（默认关，云上安全） |
| `FLAG_ATTACHMENT` | `true` | — | 附件功能开关 |
| `FLAG_EXTERNAL_DS` | `false` | — | 外部数据源开关 |
| `CORS_ORIGINS` | `["http://localhost:8080","http://localhost:5173"]` | ✅ | 前端域名白名单（JSON 数组字符串） |
| `WS_MAX_CONNECTIONS / TASK_CONCURRENCY_LIMIT` | `10 / 3` | — | 2C2G 上限，勿调大 |

## 5. 生产上云清单

1. **密钥**：生成并注入 `OIDC_RSA_PRIVATE_KEY`、`APP_ENCRYPTION_KEY`、`OIDC_CLIENT_SECRET`、`DB_PASSWORD`、`MYSQL_ROOT_PASSWORD`（建议用密钥管理/环境注入，勿写 `.env` 进 git）。
2. **HTTPS**：前置网关（Nginx/Caddy/云 LB）终结 TLS；`OIDC_ISSUER`、`CORS_ORIGINS`、`OIDC_REDIRECT_URI` 改为公网 HTTPS 地址；WS 经网关 `wss`（nginx 需配置 `Upgrade`/`Connection` 头，参考 `frontend/nginx.conf`）。
3. **Redis 持久化**：开启 AOF（`docker run` 或 compose 的 redis command 加 `--appendonly yes`），防 WS seq 丢失回卷。
4. **备份**：定期备份 `bia_mysql_data` 卷（mysqldump 三个库）；迁移用 `alembic upgrade head` 幂等可重放。
5. **安全默认**：`flag_command_exec=false`；数据源只读账号；SQL 白名单校验（仅 SELECT）；附件类型/大小限制；90 天物理清理任务（task_logs / messages 软删，见数据模型设计.md）。
6. **资源**：按 2C2G 收敛——backend 单进程 3 worker 队列、连接池 5+5；MySQL `buffer_pool` 建议 192M；Redis `maxmemory` 建议 128M。

## 6. 升级与重建

```bash
# 拉取新代码后重建 backend/frontend
docker compose up -d --build backend frontend

# 改动了 MySQL 初始化脚本或想重置全部数据（会清空三个库）
docker compose down -v && docker compose up -d --build

# 仅重置场景示例数据（重建库）
docker compose up -d --force-recreate backend   # entrypoint 会重跑 gen_*（drop+create）
```

## 7. 故障排查

| 现象 | 原因 | 处置 |
|---|---|---|
| `docker: Cannot connect to the Docker daemon` | Docker Desktop 未启动 | 启动 Docker Desktop，等待引擎就绪后再 `up` |
| backend 日志 `passlib` / `ValueError: password cannot be longer than 72 bytes` | bcrypt 版本不兼容 | `requirements.txt` 已固定 `bcrypt==4.0.1`；勿升级 bcrypt ≥5 |
| backend 日志 `TypeError: object NoneType can't be used in 'await' expression`（asyncmy close） | asyncmy 0.2.x `close()` 是同步方法 | 已修复（`conn.close()` 不 await）；勿改回 |
| backend 日志 `TypeError: can't compare offset-naive and offset-aware datetimes` | MySQL DATETIME naive 比较 | 已统一 `_now()`（naive UTC）；新代码比较时间一律用 naive UTC |
| 登录 500 `Access denied ... to database 'scenario_goods'` | bia 用户无场景库权限 / 密码漂移 | `docker compose down -v && up` 重建（init 脚本预建库授权）；检查 DB_PASSWORD 与 MYSQL_PASSWORD 一致 |
| 任务 `failed`，错误 `Access denied (using password: YES)` | seed 数据源密码与 MySQL 不一致 | seed 已改为引用 `settings.DB_PASSWORD` 并幂等更新；重建 backend |
| 前端 502 / WS 连不上 | backend 未就绪或反代配置问题 | `docker compose ps` 确认 backend healthy；检查 `frontend/nginx.conf` 反代目标 |
| 修改代码后不生效 | 镜像未重建 | `docker compose up -d --build backend`（或 frontend） |
| 忘记密码 / 登录态全失效 | RSA 私钥未持久化 | 生产必须配置 `OIDC_RSA_PRIVATE_KEY`；重置需重建 auth_users（`docker compose down -v && up`） |

## 8. 运维常用查询

```bash
# 表/行数健康检查
docker exec bia-mysql-1 mysql --batch --skip-column-names -ubia -pbia_password -e \
  "SELECT COUNT(*) FROM bia.analysis_tasks; SELECT COUNT(*) FROM scenario_goods.fact_sku_daily; SELECT COUNT(*) FROM scenario_inventory.fact_inventory_daily;"

# 任务状态分布
docker exec bia-mysql-1 mysql --batch --skip-column-names -ubia -pbia_password -e \
  "SELECT task_status, COUNT(*) FROM bia.analysis_tasks GROUP BY task_status;"

# LLM 调用记账
docker exec bia-mysql-1 mysql --batch --skip-column-names -ubia -pbia_password -e \
  "SELECT status, COUNT(*), ROUND(SUM(cost),4) FROM bia.llm_calls GROUP BY status;"
```
